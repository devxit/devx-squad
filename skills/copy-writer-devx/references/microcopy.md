# Microcopy e UX writing

Leia quando o modo for **Microcopy / UX Writing** (não confundir com **prompt de interface** no `SKILL.md` — limites de 1–4 palavras só lá).

**Turno único:** não exige FASE 1 completa de LP nem `site-par-v1`, salvo pedido explícito de SEO.

## Tipos

| Tipo | Objetivo | Tom |
| --- | --- | --- |
| Erro | Explicar o que falhou + ação | Claro, sem culpar o usuário |
| Empty state | Orientar primeiro passo | Encorajador, uma ação |
| Onboarding | Reduzir atrito no fluxo | Curto, sequencial |
| Tooltip | Contexto pontual | 1 frase |
| Modal | Confirmar ou alertar | Título + corpo + ações |
| Validação de formulário | Corrigir entrada | Específico ao campo |

## Limites sugeridos (não aplicar a páginas web)

| Elemento | Guia |
| --- | --- |
| Botão primário | 1–4 palavras |
| Botão secundário | 1–5 palavras |
| Título de modal | ≤8 palavras |
| Corpo de erro | 1–2 frases curtas |
| Tooltip | ≤120 caracteres |
| Empty state título | ≤6 palavras |
| Empty state corpo | ≤2 frases |

Frases completas são **permitidas** aqui (diferente do modo prompt UI com H2 ≤4 palavras).

## Estrutura de saída

1. **Contexto** — tela, estado, usuário, restrição técnica se houver.
2. **Recomendação** — princípio UX em 1–2 frases.
3. **Variantes** — 2–3 opções (A recomendada + alternativas).
4. **Uso** — quando preferir cada variante (se relevante).

## Checklist

- Verbo de ação no CTA.
- Evitar “Ocorreu um erro” sem orientação.
- Não inventar motivo técnico falso.
- Alinhar vocabulário ao produto (glossário do brief).
